## M2-M3: parse, layout, control flow, data flow, hazards, coverage

- Stage B (`stages/parse.py`): `preprocess_all` (cobc -E in the toolchain image, cached under `W/.phase0-cache`) -> `tokenize` -> `parse_source` -> `lower_program` (typed IR). Programs are chosen by inventory classification (content), not by suffix. Result on D1+D2: all 38 programs parse strictly (14 corpus programs = 101 paragraphs, matching the task statement; 24 semantics programs, not 25).
- Stage C (`stages/layout.py`): field ids are qualified paths from level 01/77, `PROG.` prefix only for multi-program workspaces (Phase 1's convention). FILLERs get `FILLER#k` so every byte has an entry, but they are excluded from unit reads/writes (no program can name them). `byte_length` is ONE occurrence (`unit_size`), `offset` is the first occurrence relative to the 01 record; `occurs` gives the count. `semantic_type` maps datadiv's PicInfo: numeric -> decimal(digits, scale, signed); everything else elementary -> alphanumeric(length); groups -> group(unit_size). RETURN-CODE is added as a field only when a unit touches it.
- Storage model (`stages/storage.py`): one rule replaces separate group-expansion and REDEFINES logic: a reference touches every elementary item whose bytes overlap its bytes, over all OCCURS occurrences, within one storage area (a 01 and its REDEFINES chain; all records of an FD). Chose byte overlap over `analysis.item_aliases` because item_aliases works on names (ambiguous across records) and returns groups and ancestors, not elementary items.
- Stage E (`stages/dataflow.py`): effects from the IR (same name resolution as the checker). Definitions (also for the gold guide): reads = elementary items whose value at entry may be used; writes = items some statement may store into. A write that does not cover the whole item (subscripted, reference-modified, OCCURS element, partial overlap) also counts as a read, because the bytes it does not write pass through. Statements the IR does not lower (INSPECT, FUNCTION calls) fall back to the syntax tree with every operand read (over-approximation, confidence 0.8 on that unit); CALL/EXEC operands are treated as written too.
- **Fix found while checking PAYROLL output:** READ first counted as a partial write of the record (so every record field was also a read). A successful READ replaces the whole record and a failed one leaves it untouched, so neither depends on the old value; changed to a full write.
- Stage D (`stages/control.py`): from the syntax tree (complete where the IR gives up). `performs` = named targets, THRU ranges expanded to every paragraph, a section named as itself; `perform_thru` keeps the (first, last) pairs. Fall-through unless the last top-level statement always leaves (STOP RUN, GOBACK, EXIT PROGRAM, GO TO without DEPENDING). Dynamic CALL resolved when every store into the item (VALUE + MOVEs) is a literal. ALTER and partially overlapping THRU ranges become hazards.
- Units: one `program` unit (id = PROGRAM-ID) + sections (span = header to end of last paragraph, facts = union of its paragraphs) + paragraphs. A paragraph the verifier synthesises for a section's leading sentences (same name as the section) is merged into the section unit.
- **Verifier bug found (TEAM_NOTES 5):** `parser.py` leaves `Paragraph.end_line` at the header line when a SECTION header follows the paragraph (FALLTHRU: P-EXIT 26-26 instead of 26-31, S2-B 36-36). Found because coverage reported 6 unexplained lines in FALLTHRU. Phase 0 computes paragraph ends from the token stream instead; after the fix D1+D2 have 0 unattributed lines (3256 lines: 3001 attributed, 249 comment, 6 now attributed).
- Stage F (`stages/hazards.py`): Phase 1's rules ported 1:1 onto IR statements (same gap ids, messages, severities); arithmetic inside IR-unsupported statements is scanned on the syntax tree. Unit-level G-GOTO / G-FALLTHROUGH / G-PACKED as in Phase 1.
- Coverage (`stages/coverage.py`): token regions (identification/environment = structure; data = inside an entry/FD/header; procedure = inside a unit span or header). Lines without tokens: COPY statements (attributed), compiler directives and preprocessor-dropped text (listed with reason).
- Tolerant fallback (`stages/tolerant.py`): Phase 1's analyser per rejected file, tagged `tolerant`, confidence 0.6; field types still come from `datadiv.parse_pic` (same PICTURE semantics), but no layout facts. Only known failure modes of the regex analyser are caught (ValueError, KeyError, ...); anything else propagates.
