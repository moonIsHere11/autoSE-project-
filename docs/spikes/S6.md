# Spike S6 — ACCEPT parsing, DISPLAY formats, layouts, encodings, time

**Goal:** learn (by probing GnuCOBOL 3.2 with `-std=default`) how input text becomes field values,
how values are displayed and laid out in bytes, and how to make time deterministic.
**Result: GO** — all behaviours are deterministic and documented below; several are surprising
and are exactly the semantics generated code tends to get wrong.

Reproduce: `bash docs/spikes/s6/run.sh` and `bash docs/spikes/s6/run_more.sh`.

## 1. ACCEPT (from stdin) into fields

One line is consumed per ACCEPT. Observed rules:

| Target usage | Rule | Examples (input → stored value) |
|---|---|---|
| numeric DISPLAY (incl. SIGN SEPARATE) | take the **first *byte-length* characters** of the line, then de-edit: optional leading `-`/`+` (spaces allowed before it and between sign and digits), digits, at most one `.` decimal point; `,` is ignored; then MOVE with decimal alignment and high-order truncation | `123.45`→`9(3)V99` **123.40** (window "123.4"); `-99999`→`S9(5)` **−9999** (window "-9999"); `12345`→`S9(3) SIGN LEADING SEPARATE` **+234** (window "1234") |
| COMP / BINARY, COMP-3 | the **whole line** is de-edited, then MOVEd (decimal alignment, high-order truncation to the PIC digits) | `-1234.567`→`S9(3)V99 COMP-3` **−234.56**; `12345`→`S9(4) COMP` **+2345** |
| COMP-5 | whole line, **not truncated to the PIC** — wraps at the binary width | `99999`→`S9(4) COMP-5` **−31073**; `12345`→`S9(4) COMP-5` **+12345** |
| alphanumeric `X(n)` | first n characters, space padded | `ABCDEF`→`X(3)` "ABC" |

* Invalid text gives **zero**: `abc`, `1a2`, `1e3`, `--5`, `12.3.4` (into a V99 field), `5-` into
  V99/COMP-3 fields. Trailing minus `5-` gives **+5** in an integer field (sign ignored) but **0** in
  a `V99` field — irregular; generators avoid trailing signs except as an explicit "invalid" strategy.
* `-0` into a signed DISPLAY field stores a **negative-zero overpunch** (raw `0000p`), although
  DISPLAY prints `+00000`. Bytes differ if the field is later written to a file or displayed via a
  group/REDEFINES.
* EOF (fewer lines than ACCEPTs, or empty stdin): no error, exit 0; the field keeps zero/spaces.
* A last line without a trailing newline is read normally.

**Canonical input forms the generator emits** (strategy `canonical`): `[-]digits[.digits]` with no
spaces, no `+`, no thousands separator, length ≤ the field's byte length for DISPLAY fields (so the
value is entered exactly). Overlong / invalid forms are generated only by the explicitly named
strategies `overlong` and `invalid_text`, whose interpretation is whatever GnuCOBOL does (the oracle
decides; the input model then records the *text* fed, not an intended value).

Consequence for T2a: the declared domain of an ACCEPTed DISPLAY field is the set of canonical
texts that fit in the window, e.g. `S9(2)` → texts for −9..99 (not −99..99).

## 2. DISPLAY formats (`pretty-display: yes`)

| PIC / usage | value | DISPLAY output | bytes |
|---|---|---|---|
| `9(3)` | 7 | `007` | 3 |
| `S9(3)` | −7 / +7 | `-007` / `+007` (sign always shown, leading) | 3 |
| `S9(3)V99` | −1.5 | `-001.50` (decimal point inserted) | 5 |
| `9(3)V99` | 1.5 | `001.50` | 5 |
| `V99` / `SV99` | .25 / −.25 | `.25` / `-.25` | 2 |
| `S9(3) SIGN LEADING SEPARATE` | −7 | `-007` | 4 |
| `S9(3) SIGN TRAILING SEPARATE` | −7 | `007-` (**sign trails**) | 4 |
| `S9(3) SIGN LEADING` / `TRAILING` (embedded) | −7 | `-007` | 3 |
| `S9(5)V99 COMP-3` | −123.45 | `-00123.45` | 4 |
| `9(4) COMP-3` | 1234 | `1234` | 3 |
| `S9(4) COMP` | −123 | `-0123` | 2 |
| `9(9) COMP` | 123456789 | `123456789` | 4 |
| `S9(18) BINARY` | −1 | `-000000000000000001` | 8 |
| `S9(4) COMP-5` | −123 | `-00123` (**digits = binary capacity**, 5 for 2 bytes) | 2 |
| `9(2) COMP-5` | 7 | `007` (1 byte → 3 digits) | 1 |
| `9(3)PP` | 12300 | `12300` | 3 |
| `PP9(2)` | .0012 | `.0012` | 2 |
| `X(5)` | "AB" | `AB   ` | 5 |
| `X(5) JUSTIFIED RIGHT` + `VALUE "AB"` | | `AB   ` (VALUE is not justified) | 5 |
| group | | raw bytes of the group (e.g. `GG01r\x01,`) | sum |

`FUNCTION BYTE-LENGTH(x)`, `FUNCTION LENGTH(x)` and `LENGTH OF x` all return the storage size in bytes
for these items (COMP-3 `S9(5)V99` → 4), so the layout probe can use `FUNCTION BYTE-LENGTH`.

## 3. Arithmetic facts used by the semantics model
* ROUNDED (default mode) = **round half away from zero**: 2.45→2.5, −2.45→−2.5, 2.55→2.6.
* Without ROUNDED: truncation toward zero (−0.04 into `S9(3)V9` → 0.0).
* **Arithmetic and MOVE results never produce negative zero** (`−5 * 0` → `+000.0`, `MOVE -0` → `+000`).
* High-order truncation without SIZE ERROR: `COMPUTE X = 12345.6` into `S9(3)V9` → 345.6; MOVE the same.
* MOVE of a negative value to an unsigned field drops the sign (`-5` → `005`).

## 4. Record encodings (fixed-length SEQUENTIAL file, verified with `od`)

| Field | value | bytes |
|---|---|---|
| `S9(3)` DISPLAY | −123 | `31 32 73` = "12s" — **ASCII overpunch: negative last digit = 0x70 + d** (`p`..`y`) |
| `S9(3)` DISPLAY | +123 | `31 32 33` (positive: plain digits, no overpunch) |
| `S9(3)` COMP-3 | −123 | `12 3D` (sign nibble D; C for positive; F for unsigned) |
| `S9(4)` COMP | −123 | `FF 85` — **big-endian** (`binary-byteorder: big-endian`) |
| `S9(4)` COMP-5 | −123 | `85 FF` — **native little-endian** |
| `S9(3) SIGN LEADING SEPARATE` | −123 | `2D 31 32 33` = "-123" |
| `X(3)` | "AB" | `41 42 20` |

Fixed SEQUENTIAL records are concatenated with no delimiter (22-byte record × 2 = 44 bytes).

## 5. LINE SEQUENTIAL
* WRITE trims trailing spaces and appends `\n`: `"AB      "` → `AB\n`; all spaces → `\n`.
* READ pads short lines with spaces. A line **longer than the record is split**: first READ gets the
  first 8 bytes with FILE STATUS `06`, the next READ gets the remainder (`IJ      `, status `00`).
* A final line without `\n` is read normally; then status `10` (EOF).
* Runtime knobs (defaults recorded in every report): `COB_LS_FIXED=false`, `COB_LS_VALIDATE=true`,
  `COB_LS_NULLS=false`, `COB_LS_SPLIT` (observed: split), `COB_FILE_PATH=.`.

## 6. ASSIGN names
* `ASSIGN TO "LIT.DAT"` → file `LIT.DAT` in the cwd (after an env lookup of `DD_LIT_DAT` etc.).
* `ASSIGN TO PLAINNAME` (not a data item, `assign-clause: dynamic`) → file `PLAINNAME` in the cwd.
* `ASSIGN TO WS-NAME` (a data item) → dynamic; out of scope for automatic channel discovery unless
  the manifest names the file.

## 7. Time
* `COB_CURRENT_DATE="2024/01/15 10:30:00"` sets the date but TIME still shows real hundredths
  (`10300014`) → **not deterministic**.
* **libfaketime** `LD_PRELOAD=/usr/lib/x86_64-linux-gnu/faketime/libfaketime.so.1
  FAKETIME="2024-01-15 10:30:00"` freezes DATE, TIME (`10300000`) and `FUNCTION CURRENT-DATE`
  completely; two runs identical.
* Java under libfaketime with `FAKETIME_DONT_FAKE_MONOTONIC=1` gets the frozen wall clock
  (`2024-01-15T10:30`) and `Thread.sleep` still works (no JVM hang).
* Go binaries read the clock through the vDSO without libc, so libfaketime cannot fake them; Go
  targets must use the injected clock (`COBOL_VERIFIER_FAKE_TIME`) — see LIMITATIONS.

## 8. Relevant `default.conf` settings (recorded in reports)
`binary-size: 1-2-4-8`, `binary-truncate: yes`, `binary-byteorder: big-endian`, `pretty-display: yes`,
`filename-mapping: yes`, `assign-clause: dynamic`, `arithmetic-osvs: no`, `move-ibm: no`,
`perform-osvs: no`, `defaultbyte: init`, `numeric-literal-length: 38`.

## 9. JVM start-up
10 runs of a trivial class with `-Xshare:auto -XX:TieredStopAtLevel=1`: 1.22 s → ≈120 ms per case.
With 4 parallel workers, ~150 fast-mode cases cost ≈5 s.
