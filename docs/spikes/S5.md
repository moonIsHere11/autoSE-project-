# Spike S5 — COBOL front end: ProLeap vs hand-written subset parser

Status: done. Ran over the time box (~1 h 50 min) because the shared WSL VM ran out of memory and
stopped responding for ~15 min mid-spike (§2); all results below were run and observed.
Date: 2026-11-06. Toolchain image `cobol-verifier-toolchain:0.1.0` (GnuCOBOL 3.2.0, OpenJDK
17.0.20.1, Maven 3.8.7).

## Goal

Decide how the verifier gets a COBOL front end for (a) DATA DIVISION parsing (levels, PIC, USAGE,
OCCURS, REDEFINES, VALUE, 88s, FD/SELECT/ASSIGN/ORGANIZATION) and (b) a PROCEDURE DIVISION subset
lowered to a typed IR with exact source line numbers, rejecting anything outside the subset *by name*.
Input is `cobc -E` output. Spec rule: default to hand-written unless ProLeap is clearly cheaper.

**Decision: hand-written Python parser on `cobc -E` output.** ProLeap is MIT-licensed and builds
with the image's JDK 17, but it is not on Maven Central and is not cheaper to integrate (§4–§5). The
ProLeap parsed every sample without error, but it needs a 14 MB jar set built from source, costs
1.7–3.5 s of JVM time per program, reports wrong line numbers on original fixed-format source, and
treats `D` lines differently from GnuCOBOL.

## 1. The `cobc -E` output format (GnuCOBOL 3.2, `-std=default`, fixed-format input)

Observed on the three samples (`docs/spikes/s5/out/*.E.cob`; view with `cat -A`):

1. **Free-form-like, not fixed format.** Each emitted source line is `" " + text`: exactly one leading
   space, then the content of columns 8–72. Sequence area (1–6), indicator (7) and identification area
   (73–80) are gone; `FIO00003` in cols 73–80 vanished. Original indentation is lost and **every run of
   blanks/tabs outside literals is collapsed to one space**, so *columns in the `-E` file are not original
   columns*. Only line numbers survive. Lines may be longer than 72 chars (joined continuations) and may
   carry a trailing space (after a literal or a removed `*>` comment).
2. **`#line N "file"` markers.** The file starts with `#line 1 "arith.cbl"` (path exactly as passed to
   cobc). Each COPY emits `#line 1 "<copybook path as opened>"` before the copybook text and
   `#line <line of the COPY statement> "<parent>"` after it. The line following a marker *is* line N.
   No other `#` lines appeared. (Note: on the case-insensitive `/mnt/d` drvfs mount the copybook was
   reported as `"CUSTREC.CPY"` although the file is `CUSTREC.cpy` — presumably cobc tries `.CPY` before
   `.cpy` and drvfs matches case-insensitively; on a case-sensitive fs it should report the real
   name. The parser must take the marker string verbatim and map it back to a path itself.)
3. **1:1 line preservation within a file.** `arith.cbl` 99 lines → 100 lines (= marker + 99). Comment
   lines (`*`) and `D` debug lines become **empty lines**; a continuation line (`-` in
   col 7) becomes an empty line and its text is **joined onto the previous line** — so a token's line is
   the line where it *starts*, which is the right thing to report. The COPY line itself appears twice
   (` ` before the copybook marker, and an empty line after `#line 15 "fileio.cbl"`) — harmless.
4. **Literals are verbatim**: doubled quotes kept (`'IT''S A …'`, `"a  b"";c,d. "`), inner blank runs kept
   (`'line  with   spaces'`), `x'41424344'` kept, `*>` inside a literal kept. The continued literal
   `'IT''S A VERY LON` + `-    'G MESSAGE…'` arrives as one literal on line 38.
5. **Separators `,` and `;` are removed** outside literals/PIC strings: `move 1 to a-num, e-pic; move 'xy'`
   → ` move 1 to a-num e-pic move 'xy' to f-pic`; `add 1, 2 to a-num` → ` add 1 2 to a-num`.
   Commas/periods inside PIC strings are kept (`-Z,ZZZ,ZZ9.99`, `$$$,$$9.99-`).
6. **`*>` floating comments are removed**; **case is preserved** (lower-case source stays lower case);
   tabs are collapsed like spaces.
7. **COPY … REPLACING is applied** (`:PFX:-REC` → `CUST-REC`); a continued COBOL *word*
   (`j-id-is-` / `-    long`) is joined (`j-id-is-long`, with a `-Wdialect` warning).
8. **One-way artifact.** Feeding `-E` output back to `cobc -E -free` does *not* honour the marker: the
   output began `#line 1 "/w/out/arith.E.cob"`, `#area_a`, `line 1 "arith.cbl"`. We always compile the
   original source and use `-E` only for parsing; the tokenizer rejects any unknown `#…` line.

Excerpt (`fileio.E.cob`, `$` = end of line):

#line 1 "CUSTREC.CPY"$
$

$

**Consequence for the parser:** the hard parts of fixed-format lexing (areas, indicator column,
continuation, comment lines, COPY/REPLACING, separators) are done by cobc. Our reader only needs a
`#line` file/line stack; diagnostics carry `(file, line)` and no column (the column within the `-E` line
is available but is not an original column).

## 2. ProLeap COBOL parser

### Obtaining it, license, Java

* Repo `github.com/uwol/proleap-cobol-parser`, MIT (`LICENSE`, pom `<licenses>`, GitHub API
  `"spdx_id": "MIT"`), not archived, last push 2026-03-01 (`main` = `d1bfe75bdd6d…`).
* **Not on Maven Central**: `search.maven.org` query `proleap` → `"numFound":0`;
  `https://repo1.maven.org/maven2/io/github/uwol/proleap-cobol-parser/maven-metadata.xml` → HTTP 404.
  README: *"To include the parser in your Maven project build it and add the dependency"*
  (`io.github.uwol:proleap-cobol-parser:4.0.0`). GitHub tags only go up to `v2.4.0`; `main` is `4.0.0`.
  So the image would have to download a source zip pinned by sha256 (`97fe0860…0474` for the `main` zip
  fetched today) and run `mvn package` at image-build time.
* pom: `maven.compiler.source/target 17` (README: "Building requires a JDK 17") — matches the JDK 17
  already in the image. Dependencies: `org.antlr:antlr4` **and** `antlr4-runtime` 4.7.2, `slf4j-api`
  2.0.9 (junit/logback for tests). Size: `Cobol.g4` 3,269 lines + `CobolPreprocessor.g4` 670 lines,
  1,119 main Java files; the built jar is 2.5 MB (+ 1.4 MB sources jar).
* API: `new CobolParserRunnerImpl().analyzeFile(File, CobolSourceFormatEnum)` or
  `analyzeFile(File, CobolParserParams)` (charset, copybook dirs/extensions/files, dialect
  `ANSI85|MF|OSVS`, format, `ignoreSyntaxErrors`). Returns an ASG (`Program → CompilationUnit →
  ProgramUnit → DataDivision / ProcedureDivision → Paragraph → Statement(StatementType)`), every element
  has `getCtx()` → ANTLR context → `getStart().getLine()`.
* Source formats (`CobolPreprocessor.CobolSourceFormatEnum`): `FIXED` (1–6 seq, 7 indicator, 8–72),
  `TANDEM` (col 1 indicator, code from col 2, no right margin), `VARIABLE` (1–6, 7, 8–∞).
  **`cobc -E` output is exactly `TANDEM`** (one leading blank = indicator column) *except* for the
  `#line` lines: `#` is in ProLeap's indicator set `([ABCdD$\t\-/*# ])` but falls to the `default →
  NORMAL` branch of `CobolLineReaderImpl`, so `line 1 "arith.cbl"` would reach the COBOL grammar. They
  must be blanked before parsing (keeps line numbers aligned with the `-E` file; we then map back with our
  own `#line` table). Feeding the *original* source instead lets ProLeap run its own COPY/REPLACING —
  a second preprocessor that can disagree with cobc — and it did (line numbers and `D` lines, below).

4. **Line numbers on original fixed-format source are wrong** (ProLeap reports lines of its own
   preprocessed text):
   * after a **continuation line** every later line is off by −1: `arith.cbl` `ACCEPT WS-N` is source
     line 42, ProLeap says 41; in `probe.cbl` `goback` is line 29, ProLeap says 28;
   * after a **COPY** every later line is shifted by the copybook length: `fileio.cbl` `FD RPT-FILE` is
     line 16, ProLeap says 28; paragraph `0000-START` is line 46, ProLeap says 58.

   On `-E` text with `#line` blanked, ProLeap's line = `-E` line, and our `#line` table maps it back
   exactly (`ACCEPT` → E-line 43 → `arith.cbl:42`; `CUST-REC` → E-line 19 → `CUSTREC.CPY:2`).
5. **Semantic divergence from GnuCOBOL on original source:** the `D` debug line
   (`D    display 'debug line'`) became a real `DISPLAY` statement in ProLeap's ASG; GnuCOBOL treats it as
   a comment (no `WITH DEBUGGING MODE`) and the compiled program never prints it. On `-E` input the line
   is already gone. So if ProLeap were used, it would *have* to be fed `-E` output, not the original.

What a real integration needs: `ProLeapDump.java` is 82 lines and only dumps statement *types*,
line numbers and raw clause text. Lowering to our IR needs a mapper for every subset construct —
`MOVE/COMPUTE/ADD/SUBTRACT/MULTIPLY/DIVIDE` (each has several syntactic formats, e.g. ADD … TO / ADD
… TO … GIVING / ADD CORRESPONDING), `ROUNDED`, `REMAINDER`, `[NOT] ON SIZE ERROR`, `IF/EVALUATE`
over ProLeap's condition classes (see the depth of the tree above), `PERFORM` (procedure vs inline;
`TIMES/UNTIL/VARYING`), arithmetic expression trees, file statements, data clauses — plus a JSON
schema mirrored by a Python decoder. Estimate: 600–900 Java LOC + ~300 Python LOC, plus the
`#line`-blanking/remapping wrapper, plus an image-build step.

### Lexical / syntactic gotchas (observed or confirmed on the samples)

| # | Issue | How the -E input looks | Handling |
|---|---|---|---|
| 1 | PIC string ending in the separator period | `PIC 9.`, `PIC -Z,ZZZ,ZZ9.99.`, `PIC $$$,$$9.99-.` | lexer mode after `PIC`/`PICTURE` [`IS`]: take the maximal non-blank run, strip one trailing `.` (and `,`/`;`) — a picture can't end in `.` |
| 2 | Period: separator vs decimal point | `VALUE 12.5.`, `VALUE .075.`, `1234.567`, `END-IF.` | `.` is a separator only when followed by blank/EOL; numeric literal regex `[+-]?(\d*\.\d+|\d+)` tried first |
| 3 | Words that start with digits | `0000-MAIN`, `1000-READ`, `2000-EXIT` | word regex allows a leading digit; numeric only if all digits and not followed by `-`/letter |
| 4 | Signed literals vs binary minus | `* -2 ** 2`, `VALUE -7`, but `A - 2` | sign belongs to the literal only if directly attached; COBOL requires blanks around binary operators |
| 5 | Doubled quotes, both quote kinds | `'IT''S …'`, `"a  b"";c,d. "` | `'(?:[^']|'')*'`; keep raw text, unescape when building the IR; inner blanks preserved by cobc |
| 6 | Literal prefixes | `x'41424344'` (also `Z'…'`, `N'…'`, `NX'…'`) | prefix + quote with no blank → one token; reject everything but `X` |
| 7 | Continuation lines | joined by cobc; continuation line becomes empty | nothing to do; token line = start line |
| 8 | `,` `;` separators | removed by cobc (`MOVE 1 TO A, B; MOVE…`) | still skip defensively; never inside literal/PIC |
| 9 | Figurative constants | `ZERO/ZEROS/ZEROES`, `SPACE(S)`, `HIGH-VALUE(S)`, `LOW-VALUE(S)`, `QUOTE(S)`, `ALL 'ab'`, `ALL "-"` | keyword table in the parser (not the lexer); `ALL lit` is a figurative form |
| 10 | Sentences vs scope terminators | `IF … DISPLAY 'EVEN' ELSE DISPLAY 'ODD'.` closes every open IF; `END-IF.`; `END-ADD`, `END-READ`, `END-EVALUATE`, `END-PERFORM` | statement parsers stop at: own `END-x`, a period, or a phrase keyword of an enclosing statement (`ELSE`, `WHEN`, `NOT ON SIZE ERROR`, `NOT AT END`) |
| 11 | No statement separators | `DISPLAY 'Q=' WS-QUOT ', R=' WS-REM DISPLAY WS-MSG` | a verb keyword ends the previous statement's operand list → need a reserved-word/verb table |
| 12 | Case | `move 1 to a-num` | upper-case words; never literals |
| 13 | Subscripts / ref-mod / qualification | `WS-AMT (WS-I)`, `A (1:3)`, `X OF Y` | `(` after an identifier = subscript; `:` inside = ref-mod |
| 14 | Implicit/abbreviated conditions | `WHEN WS-AVG > 500 AND WS-AVG NOT > 1000`, `IF A = 1 OR 2` | the hardest grammar piece: abbreviated combined relations + `NOT` rules; validate against GnuCOBOL |
| 15 | 88-level values | `VALUE 'A' 'B' 'C'`, `VALUE 'D' THRU 'F'` | list/range parser in data division |
| 16 | Phrase keywords as noise | `ORGANIZATION [IS]`, `FILE STATUS IS`, `GIVING`, `TIMES`, `USAGE [IS]`, `OCCURS 5 [TIMES]` | optional-keyword helper `opt("IS")` |
| 17 | `#line` stack | `#line 1 "CUSTREC.CPY"` … `#line 15 "fileio.cbl"` | reader tracks (file, line); unknown `#` lines are errors |

## 5. Decision recommendation

**Use the hand-written Python subset parser on `cobc -E` output** (the spec's default). Reasons:

1. **ProLeap is not clearly cheaper.** It removes grammar/tokenizer work (~900 LOC) but adds a Java ASG→JSON
   mapper of comparable size, a second model to keep in sync, and a from-source build (not on Maven
   Central) with 14 MB of transitively resolved jars in the image.
2. **Its line numbers are only right if we feed it `-E` text** (on original source they drift after
   every continuation line and COPY, and `D` lines become code). Once we feed it `-E`, the lexical
   work it saves is the part cobc already did.
3. **`cobc -E` already does the hard lexical work** (areas, continuation, comments, COPY/REPLACING,
   separators, column 72 truncation) and leaves a clean free-form token stream with `#line` markers. The
   PoC tokenizer handled all three samples with exact `file:line` in 110 lines.
4. **Named rejection with exact lines** is a first-class requirement; it falls out of a recursive-descent
   dispatch table but has to be bolted onto a full-language ANTLR parser.
5. **Same grammar as the reference.** Parsing GnuCOBOL's own preprocessed text, and validating the IR
   interpreter against GnuCOBOL, avoids a third interpretation of COBOL syntax (ProLeap's).
6. **Speed and simplicity:** ~ms in-process vs 1.7–3.5 s per JVM invocation; no new pinned artifacts;
   everything stays in typed Python.

Risk to watch: abbreviated combined relation conditions (`A = 1 OR 2`, `A > 1 AND < 9`, `NOT`) — implement
the standard rule, and if ever in doubt reject them as unsupported rather than guess.

### Consequences for the design

* `cobol/preprocess.py`: run `cobc -E` with the same `CobolConfig` flags as the build; keep the `#line`
  stack as the line map (no need for our own COPY handling). Record that columns are not preserved.
* `cobol/parser.py`: tokenizer per §3 (PIC mode, period rule, literal regex, upper-casing), verb/clause
  dispatch tables, `Unsupported(construct, file, line)`. Diagnostics report `file:line` only.
* Add `SET cond-name TO TRUE` to the subset wish-list (common in file loops; the samples avoided it).
* Copybook names in markers can differ in case from the file on disk (drvfs) — match case-insensitively.
