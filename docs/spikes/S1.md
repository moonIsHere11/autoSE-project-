# Spike S1 — `cobc` build, run, `-E`, trace

**Goal:** confirm we can build, run, preprocess and trace COBOL with the pinned GnuCOBOL, and find
the exact trace mechanism for coverage. **Result: GO.**

Reproduce: `bash docs/spikes/s1/run.sh` (from WSL, repo root). Sources: `docs/spikes/s1/`.

## Versions
`cobc (GnuCOBOL) 3.2.0`, C compiler GCC 13.3.0, math library GMP, host little-endian,
`BINARY-C-LONG 8 bytes`. Image `cobol-verifier-toolchain:0.1.0`.

## Build and run
* `cobc -x -std=default -I <copydir> PROG.cbl -o prog` → 0.2 s for a 30-line program.
* Running is cheap: 200 runs of a small program take 0.41 s (≈2 ms/run), so the COBOL side of T1
  costs almost nothing; the target side (JVM) dominates.
* `MOVE 3 TO RETURN-CODE` + `STOP RUN` → process exit code 3 (return code is observable).
* **Binaries are not reproducible** (two builds of the same source have different sha256), so the
  build cache must key on the *preprocessed source* hash (which is stable) + cobc version + flags.

## `cobc -E` (preprocess only)
* Output is a normalised, area-free text: every source line becomes one output line, prefixed with
  one space, sequence area/indicator stripped, runs of spaces between tokens collapsed to one
  (spaces **inside literals are preserved**: `"A   B  ""Q""  C"` stays intact).
* COPY books are expanded in place with line markers:
  ```
  #line 1 "S1COPY.cpy"
   01 WS-A PIC S9(5)V99 VALUE 0.
  #line 5 "S1PROG.cbl"
  ```
  Line numbers after a marker are 1:1 with the named file, so the parser can map every token back to
  `(file, line)` for feedback.
* Continuation lines (`-` indicator) are joined into one literal, including the implicit spaces up
  to column 72 (`"…CON" + "-    "TINUED…"` → `"…CON TINUED…"`), matching runtime behaviour.
* Comment lines become empty lines (line numbers preserved).
* The `-E` output is deterministic (identical sha256 across runs).

## Trace (coverage)
* Compile a second variant with `-ftraceall` (stdout identical to the untraced build — verified with
  `cmp`).
* Runtime environment variables (from `/usr/local/share/gnucobol/config/runtime.cfg`):
  * `COB_SET_TRACE=Y` — enable trace output
  * `COB_TRACE_FILE=<path>` — trace destination (default stderr; `$$` → pid; leading `+` appends)
  * `COB_TRACE_FORMAT=<fmt>` — default `"%P %S Line: %L"`; `%P` program-id (min. 29 chars, with
    prefix), `%I` program-id (no prefix), `%L` line (right-justified, 6), `%S` statement/paragraph,
    `%F` source file.
* With `COB_TRACE_FORMAT="%F|%I|%L|%S"` the output is easy to parse:
  ```
  Source: 'S1PROG.cbl'
  Program-Id:  S1PROG
  Source: S1PROG.cbl                     |S1PROG|    10|    Entry: S1PROG
  Source: S1PROG.cbl                     |S1PROG|    10|Paragraph: MAIN-PARA
  Source: S1PROG.cbl                     |S1PROG|    11|           ACCEPT
  Source: S1PROG.cbl                     |S1PROG|    25|Paragraph: CALC-PARA
  Source: S1PROG.cbl                     |S1PROG|    26|           COMPUTE
  Source: S1PROG.cbl                     |S1PROG|    14|           PERFORM
  Source: S1PROG.cbl                     |S1PROG|    14|           UNTIL
  Source: S1PROG.cbl                     |S1PROG|    15|           DISPLAY
  Source: S1PROG.cbl                     |S1PROG|    14|           VARYING
  ```
  Parsing rule: split on `|`; field 1 is `Source: <file>` padded; field 3 is the original source line;
  field 4 is either `Entry: X`, `Paragraph: X`, `Section: X`, or a statement name (PERFORM sub-steps
  `UNTIL`/`VARYING` appear as separate events). Lines without `|` are headers.
* Line numbers are **original** source lines (not `-E` lines), so trace ↔ source mapping is direct.
* Never-executed paragraphs (`NEVER-PARA`) simply do not appear → paragraph coverage =
  executed paragraphs / declared paragraphs; statement coverage = distinct executed statement
  lines / statement lines in the parsed source.

## Runtime-error behaviour (for T1 exclusions)
* `OPEN INPUT` on a missing file without FILE STATUS:
  `libcob: error: file does not exist (status = 35) for file IN-FILE ('MISSING_DAT' => MISSING.DAT)`,
  exit code 1. Rule: **stderr containing `libcob: error:` ⇒ COBOL runtime error ⇒ case excluded**
  (counted, reported).
* `DIVIDE 0 INTO X` without ON SIZE ERROR is *not* a runtime error: X is left unchanged and the
  program continues (this is a semantic the target must reproduce).
* The missing-file message shows that even a literal `ASSIGN "MISSING.DAT"` is first looked up as an
  environment variable (`DD_MISSING_DAT`, …) because `filename-mapping: yes`; the sandbox
  environment is therefore fully controlled (no inherited `DD_*`/`dd_*` variables).

## Decisions taken from this spike
* Coverage via `-ftraceall` + `COB_SET_TRACE=Y COB_TRACE_FILE=… COB_TRACE_FORMAT="%F|%I|%L|%S"`.
* Build cache key = sha256(`cobc -E` output) + `cobc --version` + flags.
* Exclusion rule for COBOL runtime errors as above.
