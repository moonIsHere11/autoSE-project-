# S4 — CrossHair for Python T2b (`diffbehavior`) and T3 (contracts)

Time-boxed spike (~1.5 h). Everything below was run inside `cobol-verifier-toolchain:0.1.0`;
every excerpt is copied from `docs/spikes/s4/out/*.out|*.err` (CrossHair's real stdout/stderr).
Results are bounded symbolic search (`method: symbolic_search`), **never** a proof.

## Goal

Decide whether CrossHair can be the Python engine for

* **T2b** — compare a trusted reference function (emitted from the COBOL IR, scaled-integer
  arithmetic) with the LLM's function over a PIC-bounded input domain, including WORKING-STORAGE
  post-state, and return concrete counterexamples;
* **T3** — check COBOL-derived contracts (pre: inputs in PIC domain; post: result in PIC domain and
  equal to an exact formula) on the LLM's function;

and pin down flags, output format, exit codes, timing, determinism and the harness pattern.

## Findings

### Q1 — `diffbehavior` on scaled-int COBOL ops

Correct-but-different implementations: no difference, and the search is exhaustive:

```
$ crosshair diffbehavior cobol_ref.ref_add_trunc llm_variants.add_ok            # rc=0, 0.66 s
No differences found. (attempted 4 iterations)
All paths exhausted, functions are likely the same!
$ crosshair diffbehavior cobol_ref.ref_round_drop2 llm_variants.round_ok        # rc=0, 0.46 s
No differences found. (attempted 8 iterations)
All paths exhausted, functions are likely the same!
```

Every planted bug is found, with small, readable counterexamples:

```
$ crosshair diffbehavior cobol_ref.ref_add_trunc llm_variants.add_bug_pymod     # rc=1, 0.47 s
Given: (a=0, b=-1),
     cobol_ref.ref_add_trunc : returns -1
  llm_variants.add_bug_pymod : returns 9999999
$ crosshair diffbehavior cobol_ref.ref_add_trunc llm_variants.add_bug_abs       # rc=1, 0.43 s
Given: (a=0, b=-1),
   cobol_ref.ref_add_trunc : returns -1
  llm_variants.add_bug_abs : returns 1
$ crosshair diffbehavior cobol_ref.ref_round_drop2 llm_variants.round_bug_trunc # rc=1, 0.49 s
Given: (v=-50),
     cobol_ref.ref_round_drop2 : returns -1
  llm_variants.round_bug_trunc : returns 0
Given: (v=50),
     cobol_ref.ref_round_drop2 : returns 1
  llm_variants.round_bug_trunc : returns 0
$ crosshair diffbehavior cobol_ref.ref_round_drop2 llm_variants.round_bug_banker # round(v/100), float; rc=1, 23.5 s

      cobol_ref.ref_round_drop2 : returns -1

          cobol_ref.ref_round_drop2 : returns -1

The idiomatic LLM version using `decimal` (`(Decimal(v)/100).quantize(Decimal(1), ROUND_HALF_UP)`)

realized values:

No differences found. (attempted 32 iterations)
Consider increasing the --max_uninteresting_iterations option.
```

Floats (`round(v / 100)`) are similar: 23.5 s to find a bug the int version finds in 0.7 s.

### Q2 — restricting inputs to the PIC domain

`add_ok_in_domain` is correct only for `|a|,|b| < 10**7`. Unrestricted, diffbehavior reports a
spurious difference outside the PIC domain:

```
$ crosshair diffbehavior cobol_ref.ref_add_trunc llm_variants.add_ok_in_domain   # rc=1
Given: (a=0, b=-20000000),
        cobol_ref.ref_add_trunc : returns 0
  llm_variants.add_ok_in_domain : returns -10000000
```

| Approach (`harness_dom.py`) | in-domain-correct candidate | real bug (`a+b`, no truncation) | Verdict |
|---|---|---|---|
| A. identical generated guard in both wrappers, `return None` when out of domain | rc=0, 16 it., *All paths exhausted* | rc=1 `Given: (a=-1, b=-9999999)` → `0` vs `-10000000` | **works** |
| B. same guard but `raise crosshair.IgnoreAttempt` | rc=0, 16 it., exhausted | rc=1, same counterexample | works, no gain over A, couples the harness to CrossHair internals |
| C. `typing.Annotated[int, "PIC S9(7)", (lo, hi)]` | rc=1 `Given: (a=0, b=-20000000)` | – | **ignored** by CrossHair |
| D. `@icontract.require` on both functions | rc=1 `Given: (a=0, b=-20000000)` | – | **ignored** by diffbehavior (no preconditions) |
| E. one function, leading asserts = domain, last assert = `llm(...) == ref(...)`, run with `crosshair check --analysis_kind=asserts` | rc=0, no output | rc=1 `harness_dom.py:109: error: AssertionError:  when calling eq_asserts_add_notrunc(-1, -9999999)` | **works**, preconditions are native |
| E'. same with `@icontract.require` / `@icontract.ensure(result == ref(...))`, `--analysis_kind=icontract` | rc=0 | rc=1 `harness_dom.py:119: error: false when calling eq_icontract_add_notrunc(-1, -9999999) (which returns -10000000)` | works |

Guards cost little on ints: A took 0.56 s vs 0.66 s unguarded.

### Q3 — mutated state (WORKING-STORAGE)

diffbehavior **does** compare argument post-state, not only return values and exceptions
(`diff_behavior.py`: `flexible_equal(args1.arguments, args2.arguments)`), and prints it:

```
$ crosshair diffbehavior state_toys.ref_para state_toys.llm_para_bug_flag   # WS is a @dataclass; rc=1, 1.69 s
Given: (ws=WS(total=0, count=0, flag=''), amt=-1),
           state_toys.ref_para : after execution ws=WS(total=-1, count=1, flag='N')
  state_toys.llm_para_bug_flag : after execution ws=WS(total=-1, count=1, flag='P')
```

Three traps found:

1. **Plain classes hide mutations.** `flexible_equal` treats two objects of the same type whose
   `__eq__` is `object.__eq__` as *equal* ("we can't do much. Assume equal"). The same bug with a
   plain `WSPlain` class gives a false all-clear:
   ```
   $ crosshair diffbehavior state_toys.ref_para_plain state_toys.llm_para_plain_bug_count   # rc=0
   No differences found. (attempted 6 iterations)
   All paths exhausted, functions are likely the same!
   ```
2. **Unrestricted state fields give spurious diffs** (e.g. `count=-2` for a `PIC 9(3)` field), so the
   object form also needs the domain guard, and dataclass reprs are not literal-parseable.
3. **Symbolic `str` inputs stall diffbehavior.** A flat wrapper `h_*(total, count, flag: str, amt)` with
   guard `flag in ("N","P")` returning `(ret, total, count, flag)` missed both planted bugs at every
   budget tried:
   ```
   q3_h_bug_count / q3_h_bug_flag (defaults):          rc=0  No differences found. (attempted 14 iterations)
   q3b_h_bug_*_mui50 (--max_uninteresting_iterations 50): rc=0  (attempted 104 iterations)
   q3b_h_bug_*_pct20 (--per_condition_timeout 20):      rc=0  (attempted 247 / 226 iterations), ~20.5 s
   ```
   Encoding the PIC X field as an index into its value set (`fi: int`, `0 <= fi < 2`,
   `flag = FLAGS[fi]`) fixes it, and the correct candidate is then exhaustively explored:
   ```
   $ crosshair diffbehavior state_toys.hi_ref state_toys.hi_llm_bug_count   # rc=1, 1.15 s
   Given: (total=9999998, count=999, fi=1, amt=-9999999),
               state_toys.hi_ref : returns (None, -1, 0, 'N')
     state_toys.hi_llm_bug_count : returns (None, -1, 1000, 'N')
   $ crosshair diffbehavior state_toys.hi_ref state_toys.hi_llm_ok          # rc=0, 1.10 s
   No differences found. (attempted 34 iterations)
   All paths exhausted, functions are likely the same!
   ```
   The *same* str-typed harness in assert mode (`crosshair check --analysis_kind=asserts
   state_toys.eq_state_bug_*`) finds both bugs in < 1 s:
   ```
   /w/state_toys.py:149: error: AssertionError:  when calling eq_state_bug_count(-9999999, 999, 'P', -1)
   /w/state_toys.py:157: error: AssertionError:  when calling eq_state_bug_flag(-9999999, 0, 'P', -1)
   ```

**Pattern that works:** a generated flat wrapper over primitives (scaled ints; PIC X with a known
value set as an index), identical domain guard, builds the state, calls the paragraph, and returns
`(outcome, field1, field2, …)` for **all** WS fields the unit may write.

Q8 (below) repeats this for the INTERFACE.md convention (fields = module attributes holding `Decimal`).

### Q4 — options, exceptions, determinism

`--exception_equivalence` (default `TYPE_AND_MESSAGE`):

```
$ crosshair diffbehavior misc_toys.ref_div misc_toys.llm_div_msg          # default; rc=1
Given: (a=0, b=0),
      misc_toys.ref_div : raises ZeroDivisionError()
  misc_toys.llm_div_msg : raises ZeroDivisionError('SIZE ERROR on DIVIDE')
--exception_equivalence SAME_TYPE, same pair:  rc=0  No differences found. (attempted 6 iterations) / All paths exhausted
--exception_equivalence SAME_TYPE, ValueError vs ZeroDivisionError: rc=1  ... raises ValueError('SIZE ERROR on DIVIDE')
--exception_equivalence ALL, ValueError vs ZeroDivisionError:       rc=0
```

Budget flags (`--help` text verified):

* `--max_uninteresting_iterations N` (default 5 when no `--per_condition_timeout`): stop after N
  consecutive iterations without new coverage. Scales with code, not time; too weak by default
  (Q3 trap 3; the `Decimal` run still took 54 s because each path may use the default per-path
  timeout of 5 s).
* `--per_condition_timeout T`: **CPU** seconds for the whole comparison/condition; when set, the
  uninteresting-iteration limit is lifted and `--per_path_timeout` defaults to √T.
  `round_ok_decimal` at T=30: 31.6 s, 24 iterations, not exhausted.
* `--per_path_timeout`: CPU seconds per path. On the easy toys `--per_condition_timeout 10
  --per_path_timeout 2` changes nothing (still exhausted in 4 iterations, 0.71 s).
* Data-dependent loop (`llm_add_slow`, `range(abs(a) % 50)`) at T=10: 200 iterations, exhausted, 7.9 s.

Determinism: see the Timing section — identical stdout across reruns.

### Q5 — output format and exit codes

diffbehavior:

| Situation | rc | stdout | stderr |
|---|---|---|---|
| no difference, tree exhausted | 0 | `No differences found. (attempted N iterations)` + `All paths exhausted, functions are likely the same!` | – |
| no difference, budget hit | 0 | `No differences found. (attempted N iterations)` + `Consider increasing the --max_uninteresting_iterations option.` | – |
| differences | 1 | per diff: `Given: (k=repr, …),` then `<fn1 right-justified> : <behaviour>` and `<fn2> : <behaviour>`; behaviour = `returns <repr>` / `raises <repr>` / `after execution <arg>=<repr>` (combined with `, `) | – |
| **function name not found** | **1** | empty | Python traceback ending `crosshair.fnutil.NotFound: Name "no_such_function" not found on object "<module 'llm_variants' …>"` |
| module not found | 2 | empty | `Unable to load "nosuchmodule.f": NotFound: Module 'nosuchmodule' was not found` |
| nondeterministic candidate | 2 | `*** Begin Not Deterministic Debug ***` dump (SMT exprs, stacks) | `Repeated executions are not behaving deterministically.` |
| side effect in candidate (file write) | 1 | `… : raises SideEffectDetected('We\'ve blocked a file writing operation on "/tmp/s4_side_effect.txt". …')` | – |
| unannotated candidate params | 0 | normal (signature taken from the annotated reference) | – |
| arity mismatch | 1 | `raises TypeError("ref_add_trunc() missing 1 required positional argument: 'b'")` | – |

Load errors (`q5b`):

| Situation | rc | stdout | stderr (last line) |
|---|---|---|---|
| `diffbehavior` with a candidate module that has a `SyntaxError` | 2 | empty | `Unable to load "llm_syntax_error.broken": SyntaxError: invalid syntax (llm_syntax_error.py, line 2)` (preceded by `Could not import your code:` + traceback) |
| `check` on the same module | 2 | empty | same |
| **`check` on an unknown function name** | **1** | empty | `crosshair.fnutil.NotFound: Name "no_such_function" not found on object "<module 'eq_harness' from '/w/eq_harness.py'>"` |

`crosshair check` (its `--help` documents 0 = no counterexample, 1 = counterexample(s), 2 = other
error — but an unknown function name also gives 1, see above): one line per failing condition, `<file>:<line>: error: <message> when calling <fn>(<positional
args>)[ (which returns <repr>)]`; nothing on stdout when it passes unless `--report_all`, which adds
`<file>:<line>: info: Confirmed over all paths.` (exhausted) or `info: Not confirmed.` (budget hit).

**Parsing + replay prototype (`parse_cx.py`)**, run over every `out/q*.out` file:

* diffbehavior: `^Given: \((?P<args>.*)\),$` → `ast.parse("f(" + args + ")", mode="eval")` → each
  keyword through `ast.literal_eval` (never `eval`). Works for ints, strs, tuples; dataclass reprs
  are rejected (`UNPARSEABLE (ValueError): ws=WS(total=-1, count=0, flag=''), amt=-9999999`), which
  is one more reason to use primitive-only harnesses.
* check: `^(?P<file>.+?):(?P<line>\d+): (?P<sev>error|info|warning): (?P<msg>.*)$`; split `msg` at
  the **last** `" when calling "`; strip `r" \(which returns .*\)$"`; `ast.parse` the call; `literal_eval`
  each positional argument (signature order).
* Concrete replay of every parsed counterexample (import both functions, call them outside CrossHair;
  full output in `out/parse_cx.txt`): 27 diffbehavior counterexamples **CONFIRMED**, including the
  `Decimal` module-global ones from Q8. For example:
  ```
  q1_round_banker: {'v': -50} -> replay CONFIRMED: ('ok', -1) vs ('ok', 0)
  q8_d_bug_round_pct30: {'total': -11, 'count': 0, 'fi': 1, 'amt': -1090} -> replay CONFIRMED: ('ok', ('ok', -1101, 1, 'N')) vs ('ok', ('ok', -1100, 1, 'N'))
  q3b_hi_bug_count: {'total': 9999998, 'count': 999, 'fi': 1, 'amt': -9999999} -> replay CONFIRMED: ('ok', (None, -1, 0, 'N')) vs ('ok', (None, -1, 1000, 'N'))
  q6_ic_add_bug: line 48: 'false' at add_bug_notrunc(-1, -9999999); line 49: 'false' at add_bug_notrunc(-9999999, -1)
  ```
  Every **NOT REPRODUCED** case was a real signal, not noise:
  ```
  q4_exc_default_msg: {'a': 0, 'b': 0} -> replay NOT REPRODUCED: ('exc', 'ZeroDivisionError') vs ('exc', 'ZeroDivisionError')   # message-only diff; replay compares types
  q5_side_effect: {'a': 0, 'b': -1} -> replay NOT REPRODUCED: ('ok', -1) vs ('ok', -1)       # artefact of the audit wall
  q5_nondet: {'a': 1234567, 'b': -1234568} -> replay NOT REPRODUCED ...; {'a': 1234567, 'b': 0} -> replay CONFIRMED ...
  q2_icr_in_domain: {'a': 0, 'b': -20000000} -> replay NOT REPRODUCED: ('exc', 'ViolationError') vs ('exc', 'ViolationError')  # icontract is off under CrossHair, on at replay
  ```
  So replay must use the same equivalence as the search, and "not reproduced" should be ERROR, not FAIL.
* The prototype parses stdout only. It reports `q5b_check_no_such_fn: no errors` for a run that
  actually exited 1 with a traceback, so the real parser must combine stdout with rc (rules below).

### Q6 — T3 contracts

icontract (`crosshair check --analysis_kind=icontract`), contracts written from the COBOL side:

```python
@icontract.require(lambda a: -P7 < a < P7)
@icontract.require(lambda b: -P7 < b < P7)
@icontract.ensure(lambda result: -P7 < result < P7)                       # contracts_toys.py:47/48
@icontract.ensure(lambda a, b, result: result == _exact_add_trunc(a, b))  # :49
def add_bug_notrunc(a: int, b: int) -> int: return a + b
```

```
$ crosshair check --analysis_kind=icontract contracts_toys.add_ok             # rc=0, 0.99 s, no output
$ crosshair check --analysis_kind=icontract contracts_toys.add_bug_notrunc    # rc=1, 0.95 s
/w/contracts_toys.py:48: error: false when calling add_bug_notrunc(-1, -9999999) (which returns -10000000)
/w/contracts_toys.py:49: error: false when calling add_bug_notrunc(-9999999, -1) (which returns -10000000)
$ crosshair check --analysis_kind=icontract contracts_toys.round_bug_banker   # rc=1
/w/contracts_toys.py:55: error: false when calling round_bug_banker(-999999950) (which returns -10000000)
/w/contracts_toys.py:56: error: false when calling round_bug_banker(-450) (which returns -4)
$ crosshair check --analysis_kind=icontract contracts_toys.round_bug_raises   # rc=1
/w/contracts_toys.py:65: error: ValueError: boom when calling round_bug_raises(777)
$ crosshair check --analysis_kind=icontract --report_all contracts_toys        # rc=1, 2.49 s
/w/contracts_toys.py:24: info: Confirmed over all paths.
/w/contracts_toys.py:25: info: Confirmed over all paths.
/w/contracts_toys.py:36: error: false when calling round_ok(-999999950) (which returns -10000000)
/w/contracts_toys.py:37: info: Confirmed over all paths.
...
```

* The reported line is the line of the violated `@icontract.ensure` decorator; the message for a
  lambda postcondition is just `false`. The verifier must keep a line→contract map.
* Bonus true positive: my "correct" `round_ok` failed its range postcondition at `v=-999999950`:
  `PIC S9(5)V9(4)` −99999.9950 ROUNDED to `S9(5)V99` is −100000.00, which does not fit. The spike's
  own reference (`ref_round_drop2`) does not model this size overflow either — CrossHair found an
  edge case the author missed.
* `--report_verbose` prints coloured, multi-line source excerpts (ANSI escapes) — not for parsing.
* Wrapping instead of editing the LLM code works (`harness_dom.eq_icontract_*` decorate a wrapper
  that calls the LLM function), so T3 does not need to modify the candidate's source.

`--analysis_kind=asserts` (leading asserts are preconditions, any later failing assert is a
counterexample):

```
$ crosshair check --analysis_kind=asserts asserts_toys.add_ok    # rc=0, 1.46 s, no output
$ crosshair check --analysis_kind=asserts asserts_toys.add_bug   # rc=1, 1.15 s
/w/asserts_toys.py:19: error: AssertionError: result out of PIC S9(7) when calling add_bug(-9999999, -1)
```

### Q8 — INTERFACE.md shape: WS fields as module attributes holding `Decimal`

`llm_globals.py` follows the Python convention (fields `ws_total`, `ws_count`, `ws_flag`, `ws_amt`
are module attributes, `accum_para()` takes no arguments, numerics are `Decimal`).
`globals_harness.py` takes scaled ints plus a flag index, writes the module attributes, calls the
paragraph, and returns `("ok", total_scaled, count, flag)` or `("exc", TypeName)`. All runs at
`--per_condition_timeout 30`:

| Candidate | diffbehavior (`d_ref` vs `d_llm_*`, `SAME_TYPE`) | assert mode (`eq_*`, `--report_all`) |
|---|---|---|
| correct | rc=0, 34.1 s, `No differences found. (attempted 49 iterations)` / `Consider increasing…` | rc=0, 30.7 s, `globals_harness.py:56: info: Not confirmed.` |
| flag set before the ADD | rc=1, 33.0 s, `Given: (total=0, count=0, fi=0, amt=-1000),` → `('ok', -1000, 1, 'N')` vs `('ok', -1000, 1, 'P')` | rc=1, **7.9 s**, `globals_harness.py:63: error: AssertionError:  when calling eq_bug(-1, 0, 1, -9999999)` |
| quantize to 0.1 (lost scale digit) | rc=1, 37.3 s, `Given: (total=-11, count=0, fi=1, amt=-1090),` → `('ok', -1101, 1, 'N')` vs `('ok', -1100, 1, 'N')` | rc=1, **9.7 s**, `globals_harness.py:68: error: AssertionError:  when calling eq_bug_round(-18, 0, 1, 0)` |

Setting module globals from symbolic values works under both drivers. diffbehavior always spends
the whole budget (it collects several diffs); assert mode stops at the first counterexample. With
`Decimal` state neither driver exhausts the correct candidate, so these units get a budget-bounded
PASS.

## Timing

## Problems / gotchas

1. **False all-clear from identity equality.** diffbehavior compares mutated arguments with
   `flexible_equal`, which declares two same-type objects *equal* if their `__eq__` is
   `object.__eq__`. A plain state class therefore hides every post-state bug (Q3, "All paths
   exhausted"). Never pass state objects; return all fields as a tuple of primitives.
2. **False all-clear from symbolic `str` in diffbehavior.** With a `flag: str` input guarded by
   `flag in ("N","P")`, two planted bugs survived 20 s / 247 iterations. Index-encode PIC X fields
   with known value sets, or use the assert-mode driver (found both bugs in < 1 s with the same
   str input). General PIC X(n) text was not tested beyond this; treat as a risk.
3. **Default budget is weak.** Without `--per_condition_timeout`, the search stops after 5
   consecutive "uninteresting" iterations (Q3 h_* stopped at 14 iterations). Always set
   `--per_condition_timeout`.
4. **`Decimal` and `float` are not symbolic.** Correct `Decimal` code: 54 s by default, ~30 s at T=30,
   never exhausted (`Consider increasing…` / `info: Not confirmed.`). Float `round(v/100)`: 23.5 s vs
   0.7 s for the int version. Expect LLM Python (which will use `decimal`) to give budget-bounded,
   weaker results; that is still a valid `symbolic_search` PASS, but never "exhausted".
5. **Exit code 1 is overloaded (both `diffbehavior` and `check`).** An unknown function name exits 1
   (same as "differences found" / "counterexample") with a traceback and empty stdout; an unknown
   module or a syntax error exits 2. Classify by stdout content, not by the exit code alone.
6. **Nondeterminism**: exit 2, and the debug dump goes to **stdout**, the one-line reason to stderr.
7. **Domain must be explicit.** diffbehavior has no preconditions; `typing.Annotated` metadata and
   `@icontract.require` are both ignored, so unrestricted inputs give spurious out-of-PIC diffs.
8. **Exception messages.** The default `TYPE_AND_MESSAGE` flags message-only differences
   (`ZeroDivisionError()` vs `ZeroDivisionError('SIZE ERROR on DIVIDE')`). Use `SAME_TYPE`.
9. **Side effects look like behavioural differences.** A blocked file write appears as `raises
   SideEffectDetected(...)` in a normal `Given:` block (rc=1), and the replay does not reproduce
   it. Classify as ERROR ("side effect in unit"), not FAIL. Never pass `--unblock`.
10. **Budgets are CPU seconds, not wall-clock.** Under a saturated host (WSL load average ~100
    during this spike, other jobs running), the same runs took 0.47 s → 249.65 s (`pymod`) and
    23.5 s → 717 s (`banker`) of wall time, with identical output. The verifier needs its own
    wall-clock kill (→ TIMEOUT).
11. **`crosshair check` is silent on PASS.** Use `--report_all` to tell "Confirmed over all paths."
    (exhausted) from "Not confirmed." (budget hit).
12. **icontract messages carry no name.** A failing lambda postcondition prints only `false`; the
    reported line is the decorator's line, so the generator must keep a line→contract map. Wrapping
    the LLM function in a generated, decorated wrapper works (no edits to LLM code).
13. **Contracts must model SIZE ERROR / truncation.** The spike's own `round_ok` contract was wrong
    (ROUNDED −99999.9950 → −100000.00 overflows `S9(5)V99`); CrossHair found it in < 1 s. Good for
    T3, but every emitted postcondition needs the same overflow semantics as the reference.
14. **Signatures**: diffbehavior builds inputs from the first function's signature; the candidate may
    be unannotated (worked), but an arity mismatch produces `TypeError` "differences". Check the
    signature before running (T0).
15. **No `--version` flag**; record the version from `importlib.metadata.version("crosshair-tool")`.
16. (Spike-only) `bash` reads a running script incrementally: editing `inner.sh` during a run
    executed a few lines of the edited file. The verifier must not edit harness files of a run
    that is still going.

## Go / No-go

**GO** for CrossHair 0.0.111 as the Python T2b/T3 engine, with these conditions:

* Every planted bug in the scaled-int toys was found in < 1 s, the float/`Decimal` ones in 6–37 s,
  with small counterexamples (`v=-50`, `v=-150`, `a=0, b=-1`). All 27 counterexamples from
  deterministic, primitive-typed harnesses were confirmed by concrete replay. Correct int
  candidates are path-exhausted in < 2 s. Output is byte-identical across reruns. T3 with
  icontract works and found a real overflow in a hand-written contract.
* **Condition 1 — harness shape.** The generated harness over primitives (scaled ints, value-set
  indices for PIC X), explicit domain, all post-state fields returned (Recommended integration). No
  state objects, no unconstrained `str` (gotchas 1–2 are silent false PASSes).
* **Condition 2 — driver.** Use `crosshair check --analysis_kind=asserts` on a generated equivalence
  function as the T2b driver rather than `crosshair diffbehavior`. In this spike it was never worse
  and was better on every axis that matters for a verifier: native preconditions, no false
  all-clear on `str` inputs, one output format and parser shared with T3, it stops at the first
  counterexample (4–5× faster on the float/`Decimal` toys), and `--report_all` gives the
  exhausted/budget signal per condition. This deviates from DESIGN.md's "diffbehavior" wording and
  needs a DECISIONS.md entry. `diffbehavior` (with `SAME_TYPE`, primitive wrappers) is still
  usable and gives nicer two-sided output.
* **Condition 3 — honest labelling.** `method: symbolic_search`; `exhausted` true only when CrossHair
  says so. Candidates written with `decimal.Decimal` (the likely LLM style) will get
  budget-bounded results only.
* **Condition 4 — post-processing.** Classify by output content, not only rc (gotcha 5); replay every
  counterexample; side effects and nondeterminism → ERROR.

**No-go items:** none blocking. Residual risks: general PIC X(n) text inputs (only a 2-value set
was tested), and large `Decimal`-heavy paragraphs, where the budget may only cover shallow paths.

## Recommended verifier integration

### Harness (T2b), one generated module per unit

Generated next to (not inside) the candidate, imported with `PYTHONPATH=<harness dir>:<candidate root>`.
All symbolic inputs are primitives: scaled ints for numeric fields, an index for PIC X fields with a
known value set (88-levels, or values seen in T1 cases). `_ref` is the trusted IR-emitted reference
(ints only); `_cand` is the adapter that loads the inputs into the candidate's representation
(INTERFACE.md: module attributes, `Decimal` or int), calls the paragraph and reads **every** field the
unit may write back as scaled ints. The template below was **not run as written**; the tested
equivalents are `globals_harness.py` (Q8) and `state_toys.eq_state_*` / `hi_*` (Q3).

```python
# _t2b_accum_para.py  (generated)
from decimal import Decimal
import _ref_prog as REF            # emitted from the COBOL IR: ints only, no Decimal/float
import prog as CAND                # candidate module (INTERFACE.md naming)

V_WS_FLAG = ("N", "P")             # PIC X value set -> symbolic index

def _scaled(d, scale):             # exact: a value with extra scale digits must not be truncated away
    v = Decimal(d).scaleb(scale)
    return int(v) if v == v.to_integral_value() else ("non-integral", str(d))

def _outcome_cand(ws_total, ws_count, ws_flag_i, ws_amt):
    CAND.ws_total = Decimal(ws_total).scaleb(-2)
    CAND.ws_count = ws_count
    CAND.ws_flag = V_WS_FLAG[ws_flag_i]
    CAND.ws_amt = Decimal(ws_amt).scaleb(-2)
    try:
        CAND.accum_para()
    except Exception as e:         # CrossHair's own control flow uses BaseException
        return ("exc", type(e).__name__)
    return ("ok", _scaled(CAND.ws_total, 2), CAND.ws_count, CAND.ws_flag, _scaled(CAND.ws_amt, 2))

def _outcome_ref(ws_total, ws_count, ws_flag_i, ws_amt):
    return REF.accum_para(ws_total, ws_count, V_WS_FLAG[ws_flag_i], ws_amt)  # same tuple shape

def t2b_accum_para(ws_total: int, ws_count: int, ws_flag_i: int, ws_amt: int) -> None:
    assert -10**7 < ws_total < 10**7          # PIC S9(5)V99   (leading asserts = preconditions)
    assert 0 <= ws_count < 1000               # PIC 9(3)
    assert 0 <= ws_flag_i < len(V_WS_FLAG)
    assert -10**7 < ws_amt < 10**7
    assert _outcome_ref(ws_total, ws_count, ws_flag_i, ws_amt) == \
           _outcome_cand(ws_total, ws_count, ws_flag_i, ws_amt)      # the equivalence line
```

Run it with **`crosshair check --analysis_kind=asserts`** (recommended T2b driver, see Go/No-go).
If the project prefers `diffbehavior`, the same module also gets two wrappers with an identical
guard that return `None` out of domain and the outcome tuple otherwise
(`d_ref(...)`, `d_cand(...)`, as in `globals_harness.py`).

### T3 (contracts), wrapper module per unit

```python
@icontract.require(lambda a: -10**7 < a < 10**7)                 # one contract per line,
@icontract.require(lambda b: -10**7 < b < 10**7)                 # generator keeps line -> contract id
@icontract.ensure(lambda result: -10**7 < result < 10**7)
@icontract.ensure(lambda a, b, result: result == _exact(a, b))   # exact COBOL formula incl. truncation/SIZE
def t3_add(a: int, b: int) -> int:
    return CAND.add(a, b)                                         # candidate code untouched
```

### Command lines

```bash
docker run --rm --network none --read-only --tmpfs /tmp \
  -e PYTHONDONTWRITEBYTECODE=1 -e PYTHONHASHSEED=0 -e PYTHONPATH=/h:/cand \
  -v <harness>:/h:ro -v <candidate>:/cand:ro -w /h cobol-verifier-toolchain:0.1.0 \
  timeout -s KILL <3*T+60> \
  crosshair check --analysis_kind=asserts --report_all --per_condition_timeout <T> _t2b_<unit>.t2b_<unit>
# T3: same, with --analysis_kind=icontract and the _t3_<unit> wrapper module
# optional diffbehavior form:
#   crosshair diffbehavior --exception_equivalence SAME_TYPE --per_condition_timeout <T> _t2b_<unit>.d_ref _t2b_<unit>.d_cand
```

* `T` = CPU seconds per unit: 30 for the default mode, 120 for `full`; leave `--per_path_timeout`
  at its default (√T) and do not pass `--max_uninteresting_iterations` (lifted by T).
* Outer `timeout -s KILL` on wall-clock (budgets are CPU time) → status `TIMEOUT`.
* Never `--unblock`, never `--report_verbose` (ANSI, multi-line) for parsing.
* `PYTHONHASHSEED=0` and `--read-only` were **not** exercised in this spike (cheap insurance only).

### Output parsing rules

`crosshair check` (T2b assert mode and T3):

1. `rc == 2` → `ERROR`; reason = last non-empty stderr line (e.g. `Unable to load
   "llm_syntax_error.broken": SyntaxError: invalid syntax (llm_syntax_error.py, line 2)`).
2. Each stdout line `^(.+?):(\d+): (error|info|warning): (.*)$`:
   * `error` and the message contains ` when calling ` → counterexample. Split at the **last**
     ` when calling `; left part is the reason (`AssertionError: …`, `false`, `ValueError: boom`);
     strip `r" \(which returns .*\)$"`; `ast.parse(call, mode="eval")`; `ast.literal_eval` each
     positional argument; zip with the generated signature. Map the line number to the generated
     assert/contract (domain lines must never appear; the equivalence/postcondition lines can).
   * `error` without ` when calling ` → `ERROR` with the message.
   * `info: Confirmed over all paths.` → that condition was exhausted; `info: Not confirmed.` → budget hit.
3. `rc == 1` with ≥ 1 counterexample → replay (below); `rc == 1` without any → `ERROR`.
4. `rc == 0` → `PASS`, `method: symbolic_search`, detail `exhausted: true` only if every condition
   printed `Confirmed over all paths.`; otherwise `exhausted: false, budget_cpu_s: T`. Never "proof".
5. Killed by the outer timeout → `TIMEOUT`.

`crosshair diffbehavior` (if used):

1. `rc == 0` and stdout line 1 starts `No differences found. (attempted N iterations)` → `PASS`;
   line 2 `All paths exhausted, functions are likely the same!` → `exhausted: true`, `Consider
   increasing the --max_uninteresting_iterations option.` → `exhausted: false`.
2. `rc == 1` and ≥ 1 `^Given: \((.*)\),$` line → counterexamples (args via `ast` keywords +
   `literal_eval`); the next two lines are `<fn> : <behaviour>`, split on the first `" : "`.
3. `rc == 1` without `Given:` (unknown function, traceback on stderr), or `rc == 2` (load error,
   nondeterminism: stderr `Repeated executions are not behaving deterministically.`) → `ERROR`.

Both modes, before reporting `FAIL`:

* Behaviour text containing `SideEffectDetected` → `ERROR` "side effect in unit" (not FAIL).
* **Replay** each counterexample concretely in a fresh sandboxed process with the same outcome
  normalisation (`("ok", fields…)` / `("exc", TypeName)`): differ → `FAIL` with the counterexample;
  identical → `ERROR` "counterexample not reproduced (nondeterminism / CrossHair artefact)".
* Keep at most a few counterexamples per unit (CrossHair already prints a small, coverage-ranked set).
